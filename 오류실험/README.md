# 오류 삽입 실험

서점 SCM 원자료에 정답을 아는 오류를 일부러 넣은 뒤, 추가 품질 점검(full)이 재주문 예측(매월 다음 30일 재주문 도서 상위 20%)을 얼마나 지키는지 확인합니다.
실제 자료에서는 품질 점검 유무에 따른 성능 차이가 거의 없었습니다. 자료가 깨끗해서 차이가 없는 것인지, 점검 규칙이 효과가 없는 것인지를 가르기 위한 실험입니다.

```
오류실험/코드/
├─ error_injection.py       실험 (교보/코드/의 적재·점검·예측 코드를 그대로 불러 씀)
└─ test_error_injection.py  단위 테스트 (가상 데이터)
```

```bash
cd 오류실험/코드
python -m unittest test_error_injection   # 테스트
python error_injection.py                 # 자료가 있을 때: 교보·예스24, 시드 10개
```

## 설계

- **오류 6종**을 재주문 이벤트·반품·월별 판매 원본 행에 같은 개수씩 넣습니다. 원래부터 점검에 걸리는 행은 고르지 않습니다.
  - 점검 규칙이 잡도록 의도한 오류: 수량 0, 완전 중복 행, ISBN 체크 숫자 오타
  - 점검 규칙에 없는 오류: 수량 단위 오류(×10), 날짜 1년 오기, 행 누락
- **비율과 반복**: 0·5·10·20%(6종 혼합)와 유형별 10%(한 유형만)를 무작위 시드 10개로 반복합니다.
- **고정**: 품질 점검 규칙은 기존 그대로입니다(넣은 오류에 맞춰 고치지 않음). 기준일·평가 대상·평가 정답은 원자료에서 만듭니다.
- **오염**: 학습 변수와 학습 라벨은 오염된 자료에서 다시 만듭니다. 오염 때문에 사라진 평가 도서는 선택될 수 없는 것으로 처리합니다.
- **비교**: 같은 오염 자료에 점검 미적용(minimal)과 적용(full)을 둘 다 적용해 시드별로 짝지어 비교합니다.
- **지표**: Precision@20%(기준일별 선정 후 합산), 보조 지표 평균 정밀도(AP), 학습 라벨 뒤집힘 비율, 오류 유형별 탐지율

## 결과 요약 (반올림)

- **탐지율**: 점검 규칙은 의도한 3종을 모두(100%) 잡았습니다. 단위 오류·날짜 오기·행 누락과 판매표 중복 행은 하나도 잡지 못했습니다(0%).
- **성능 하락**: 6종을 20% 섞으면 예측 모델의 Precision@20%가 두 서점 모두 약 2~5%p 떨어졌습니다.
- **점검 유무 차이**: 점검 유무에 따른 차이는 ±1.5%p 안이었고, 방향도 시드마다 달랐습니다. 시드 간 흔들림(약 2%p)과 구분되지 않습니다.
- **차이가 작은 이유**
  - ISBN 오타 행은 점검이 없어도 도서정보와 연결되지 않아 저절로 빠집니다. 그래서 결과가 행 누락과 같습니다. 탐지는 되지만 성능 차이는 없습니다.
  - 라벨이 "30일 안에 재주문 1건 이상"이라서 중복 행은 라벨을 바꾸지 않습니다.
  - 수량 0 행을 지우면 실제 재주문 라벨이 사라집니다(학습 라벨의 약 2% 뒤집힘).
  - 학습 라벨을 가장 많이 뒤집는 오류는 날짜 오기(약 5~6%)인데, 규칙에 없는 유형입니다.
- **판매 규칙과 비교**: 최근 판매 규칙은 오류의 영향을 거의 받지 않았습니다(±1%p). 오류 20%에서는 모델과 규칙의 격차가 약 10~12%p에서 약 6~8%p로 줄었습니다.

정리하면, 행 단위 규칙은 잡기 쉬운 오류만 잡고 성능을 해치는 오류는 놓칩니다. 그래서 다음 단계인 LLM Agent 검토는 규칙이 놓친 유형(날짜·단위·누락·판매 중복)을 정답지로 삼아 평가합니다.
